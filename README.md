# Лабораторная работа №6
## Внедрение адаптивности и развертывание приложения

### Цель работы
Внедрение менеджера состояний, добавление адаптивности и PWA, создание Tauri-приложения и развертывание на GitHub Pages.

---

### Задание

#### 1. Внедрение менеджера состояний
- Добавить Redux Toolkit для хранения значений фильтров услуг
- Использовать расширение для браузера redux-devtools
- Обеспечить сохранение состояния фильтров между переходами на страницы

#### 2. Адаптивный дизайн
- Реализовать адаптивность для трёх страниц приложения
- Настроить адаптивное отображение карточек услуг:
  - Количество колонок в зависимости от ширины экрана
  - Размеры карточек и их содержимого
  - Адаптивная навигация и элементы интерфейса

#### 3. PWA (Progressive Web App)
- Добавить возможность работы в режиме PWA
- Реализовать установку приложения на мобильные устройства
- Настроить манифест и service worker

#### 4. Нативное приложение на Tauri
- Создать простое нативное приложение на Tauri для интерфейса гостя
- Включить 3 страницы с фильтрацией и картинками
- Подключить приложение к API через IP адрес в локальной сети (не localhost)

#### 5. Развертывание
- Развернуть фронтенд на GitHub Pages
- Настроить HTTPS для безопасного доступа

---

### Порядок демонстрации

1. **PWA на мобильном устройстве**:
   - Открыть GitHub Pages с mock-данными на телефоне
   - Сохранить приложение как PWA
   - Показать работу PWA: применить фильтрацию услуг, перейти на главную и вернуться назад (должны сохраниться значения фильтров)

2. **Адаптивный дизайн**:
   - Перейти в адаптивный режим браузера
   - Показать изменение интерфейса при изменении ширины экрана
   - Объяснить настройки для:
     - Размера карточек
     - Количества колонок
     - Конкретных значений breakpoints

3. **Tauri приложение**:
   - На компьютере показать подключение Tauri к бэкенду по IP локальной сети
   - Сравнить IP сервера из консоли и в коде приложения
   - Отредактировать услуги в БД и продемонстрировать изменение в Tauri
   - Показать настройку HTTPS

---

### Контрольные вопросы

- **Flux**: архитектурный паттерн управления состоянием
- **Схема Redux**: store, reducer, dispatch, action
- **Виды нативных приложений**: PWA, Tauri, Electron и др.
- **GitHub Pages**: процесс развертывания и настройки

### Deployment диаграмма

Требуется предоставить deployment диаграмму со всеми узлами и компонентами системы:

- **Узлы системы**:
  - Фронтенд (GitHub Pages)
  - Web-сервер со статикой
  - Веб-сервис (бэкенд API)
  - База данных
  - Другие хранилища (Redis, MinIO и т.д.)

- **Соединения**:
  - Указать протоколы между узлами (HTTP/HTTPS, WebSocket и т.д.)
  - Показать API-взаимодействие между фронтендом и бэкендом
  - Разместить компоненты фронтенда и бэкенда в соответствующих узлах

### Технические требования

#### Redux Toolkit
- Хранение состояния фильтров (дата, название, цена)
- Интеграция с React компонентами
- Поддержка redux-devtools

#### Адаптивный дизайн
- Mobile-first подход
- Breakpoints для различных устройств
- Гибкая сетка карточек

#### PWA
- Манифест приложения
- Service Worker для кэширования
- Иконки для различных разрешений

#### Tauri
- Настройка подключения к API по IP
- Сборка нативного приложения
- Настройка безопасности и CORS

#### Развертывание
- Автоматическое развертывание на GitHub Pages
- Настройка HTTPS
- Конфигурация для PWA
